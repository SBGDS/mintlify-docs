The Empty state component fills a screen when there is nothing to show yet. It pairs an alert avatar and a short message with up to two actions, so users know why the screen is empty and what to do next.

## When to use it

Use the Empty state component when:

- A screen has no data because the user hasn't linked or created anything yet. For example, a dashboard with no linked bank accounts, share trading, insurance, or investment portfolios.
- You want to point users to the action that populates the screen.

Don't use it for:

- Loading states. Show a loader instead.
- Errors that block the user. Show an error message with a retry action.
- Short lists with only a few items. Show the items.

## Anatomy

| Part | Component | Purpose |
|---|---|---|
| Icon | `avatar_alert` (80 × 80) | Draws attention to the message |
| Headline | Text layer | Says what the user can do here |
| Explanation | Text layer | Explains how the user can populate, link, or update the screen |
| Primary action | `button_secondary` | Main call to action. The default label is "LINK ACCOUNTS" |
| Secondary action | `button_tertiary` | Alternative action. The default label is "OPEN AN ACCOUNT" |

## Variants and states

The Empty state has a single variant with no component properties. Its states come from the buttons it contains.

| Element | Property | Options |
|---|---|---|
| Empty state | — | One variant |
| `button_secondary` | state | `default`, `disabled`, `loading` |
| `button_secondary` | manual resize | `true`, `false` |
| `button_secondary` | icon, icon type, label | Boolean, instance swap, text |
| `button_tertiary` | state | `default`, `disabled`, `loading` |
| `button_tertiary` | icon, icon type, label | Boolean, instance swap, text |

<Note>
  The Figma frame only shows the `default` button state. Confirm with the design team before you ship the `disabled` or `loading` states inside an Empty state.
</Note>

## Accessibility requirements

- **Contrast.** Text must meet WCAG 2.1 AA: 4.5:1 for body text. Check `--color-text-primary` (`#02070d`) on `--color-background-surface-default` (`#ffffff`), which has very high contrast.
- **Focus.** Both buttons must show a visible focus ring using `--color-border-focus`. Keep the tab order top to bottom: primary action, then secondary action.
- **Touch targets.** `button_secondary` is 48 high and meets the 44 × 44 minimum. `button_tertiary` is 36 high, which is below 44. Add padding or hit-area to reach 44 on touch devices.
- **Icon.** Treat the alert avatar as decorative. Hide it from assistive technology (`aria-hidden="true"`) because the text already conveys the message.
- **Text.** Don't convey the empty state by color or icon alone. Keep the headline and explanation as real text.
- **Announcements.** If the empty state replaces content after a user action, announce the change with a polite live region.
- **Labels.** Button labels must describe the action. The Figma defaults are uppercase, so write them in sentence case in code and apply the uppercase style with CSS, so screen readers don't read letter by letter.

## Usage examples

### Dashboard with no linked accounts

Use the default content when the user has not linked any accounts.

- **Headline:** Link your bank accounts, Online Share Trading, insurance and investment portfolios here.
- **Explanation:** Explain how the user can populate, link, or update this screen.
- **Primary action:** LINK ACCOUNTS
- **Secondary action:** OPEN AN ACCOUNT
