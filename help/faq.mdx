Whether you're just getting started or running into a specific workflow question, this page collects the answers our users ask for most. Browse by topic or use your browser's find function to jump to what you need.

<AccordionGroup>
  <Accordion title="What file format do I use for pages?">
    SBGDS pages are written in **MDX** — Markdown with JSX support. Every page file uses the `.mdx` extension and should be saved inside your documentation directory (typically the root or a `docs/` folder in your repository).

    Each page must open with a YAML frontmatter block that provides at minimum a `title` and `description`:

    ```mdx my-page.mdx
    ---
    title: "My Page Title"
    description: "A brief description of what this page covers."
    ---

    Your content starts here.
    ```

    Inside the file you can use standard Markdown syntax (headings, lists, code blocks, tables) alongside SBGDS components like `<Note>`, `<Card>`, and `<Steps>`. You can also import and render custom React components if your project includes them.
  </Accordion>

  <Accordion title="How do I add a new page to the sidebar?">
    Adding a page to the sidebar is a two-step process. First, create your `.mdx` file in the appropriate directory. Then, register its path in the `navigation` array inside `docs.json`.

    ```json docs.json
    {
      "navigation": [
        {
          "group": "Getting Started",
          "pages": [
            "quickstart",
            "guides/installation",
            "guides/your-new-page"
          ]
        }
      ]
    }
    ```

    The path in `pages` is relative to your docs root and omits the `.mdx` extension. Nested paths (like `guides/your-new-page`) correspond to actual subdirectory structures in your repository. SBGDS renders the sidebar in the exact order you define — drag the entry to a new position in the array to reorder it.
  </Accordion>

  <Accordion title="Can I use custom React components?">
    Yes. SBGDS supports custom React components inside `.mdx` files. You can import and use any component that doesn't rely on browser-only APIs at module evaluation time.

    Place your components in a `components/` directory at your docs root, then import them directly at the top of an `.mdx` file:

    ```mdx my-page.mdx
    ---
    title: "API Reference"
    description: "Full API reference with interactive examples."
    ---

    import { ParameterTable } from '/components/ParameterTable'

    <ParameterTable endpoint="/v1/users" />
    ```

    For components you want available on every page without importing, add them to the `components` field in `docs.json` to register them as global MDX components.

    <Note>
      Components must be compatible with React Server Components or explicitly marked as client components. Avoid direct use of `window`, `document`, or browser-only hooks at the module level.
    </Note>
  </Accordion>

  <Accordion title="How do I preview changes locally?">
    SBGDS ships a local development server you can run with a single command. Make sure you have Node.js 18 or later installed, then run:

    ```bash
    npx mint dev
    ```

    This starts a hot-reloading preview at `http://localhost:3000`. Every time you save an `.mdx` file or update `docs.json`, the browser reflects the change instantly — no manual refresh needed.

    If you haven't installed the SBGDS CLI globally yet, do so once with:

    ```bash
    npm install -g mint
    ```

    Then you can use `mint dev` directly from any project directory.

    <Tip>
      Run `mint dev --port 3001` to start the server on a different port if 3000 is already in use on your machine.
    </Tip>
  </Accordion>

  <Accordion title="How do I set up a custom domain?">
    You can serve your SBGDS site from any domain or subdomain you own (e.g. `docs.acme.com`). The process takes about five minutes, plus DNS propagation time.

    1. In your SBGDS dashboard, go to **Settings → Domains** and enter your desired domain.
    2. Add a `CNAME` record with your DNS provider pointing your subdomain to `cname.sbgds.site`.
    3. Return to the dashboard and click **Verify DNS**. SBGDS provisions a free TLS certificate automatically once verification passes.

    Full step-by-step instructions, including notes for Cloudflare and Route 53 users, are in the [Integrations](/configuration/integrations#custom-domain-setup) guide.
  </Accordion>

  <Accordion title="What happens when I push to GitHub?">
    If you've connected a GitHub repository to your SBGDS project, every push to your configured default branch triggers an automatic deployment. Here's the sequence:

    1. SBGDS detects the push via a GitHub webhook.
    2. The SBGDS build system clones the latest commit and runs the site build.
    3. If the build passes, the new version is promoted to your live URL — typically within 30 seconds of pushing.
    4. If the build fails, your previous deployment stays live and you receive an email with the build log.

    For every **pull request**, SBGDS also creates a temporary preview deployment with a unique URL, making it easy to review documentation changes before merging. The URL is posted as a comment on the PR and as a GitHub status check.
  </Accordion>

  <Accordion title="Can multiple people edit the docs at the same time?">
    Yes — collaboration in SBGDS follows the same branching model as your code. Multiple contributors can each work on separate Git branches and open pull requests. Each PR gets its own preview deployment URL, so reviewers can inspect the rendered output before approving.

    **Team access** is managed in the SBGDS dashboard under **Settings → Team**. You can invite collaborators by email and assign one of three roles:

    | Role | What they can do |
    |---|---|
    | **Viewer** | Read dashboard, view deployments |
    | **Editor** | All Viewer permissions plus trigger manual deploys and manage redirects |
    | **Admin** | Full access including billing, domain management, and team settings |

    There is no limit on the number of team members you can invite on any paid plan.
  </Accordion>

  <Accordion title="How do I use AI tools with SBGDS?">
    SBGDS offers two ways to bring AI tools into your documentation experience.

    **For your readers — contextual AI toolbar:**
    Enable the floating toolbar that appears when a reader selects text on any page. Add the AI providers you want to expose in `docs.json`:

    ```json docs.json
    {
      "contextual": {
        "options": ["chatgpt", "claude", "perplexity"]
      }
    }
    ```

    Clicking a provider opens that AI tool with the selected text pre-loaded as context, letting readers ask follow-up questions without starting from scratch.

    **For developers — MCP server:**
    The SBGDS MCP server exposes your documentation as a queryable tool for AI coding assistants like Cursor and Claude Code. Developers add your MCP endpoint to their local config once, and the assistant can answer questions about your specific APIs and concepts without hallucinating.

    See the [Integrations guide](/configuration/integrations#mcp-server-integration) for full MCP setup instructions.
  </Accordion>
